# 階段 4 規格:美術升級(AI 產圖)

## 目標
把遊戲從程式繪圖換成**精緻 Q 版的 AI 圖**,而且換圖的過程要順、換完畫面比例要對、載入不能變慢:
- **換圖**:39 種寵物 + 炎龍、5 職業男女主人、6 位 NPC、16 種道具、登入畫面主視覺與 Logo、地面材質與樹木裝飾
- **產圖流程要快**:使用者產完一批原圖,批次去背、一鍵存進遊戲;有一頁看得到哪些圖還缺
- **比例要對**:換圖後主人、NPC、寵物的大小要合理,戰鬥畫面依角色實際大小排,不會疊在一起
- **載入不變慢**:圖片改存 WebP,登入時就在背景讀圖,第二次進遊戲幾乎不用下載

沿用階段 2 定下的原則:**有圖就用圖,沒圖就退回程式繪圖**。所以圖可以一批一批換,沒畫完也能正常玩;
右下角「美術:圖片 / 程式」開關可以隨時切回程式繪圖比較。

## 已確認的設計決定(2026-10-11、10-12 與使用者討論)
細節和被否決的方案見 `討論紀錄.md` 第 1~10 題。

|---|---|

| 配套工具 | 去背工具加批次模式、美術進度表頁、使用者放進原圖後 Claude 先看一遍 |

## 4. 去背工具(`public/tools/sprite-tool.html`)擴充
現況(2026-10-13 已讀 `sprite-tool.js`、`server.py`):目標只有寵物與 NPC 兩類;成品用 `toBlob('image/png')` 存成 PNG;
「清除雜點」會把面積小於最大一塊某個百分比的區塊清掉。

### 4.1 存成 WebP
- 成品改存 WebP 品質 90(保留透明)。2026-10-11 實測 256×256 成品:PNG 約 83~88KB,WebP 品質 90 約 14~21KB,無損 WebP 60~73KB。
- 現有 8 張 PNG(噗噗、小火妖的主圖與動作圖)轉成 WebP,刪掉 PNG。
- 開工後把品質 90 的 WebP 跟 PNG 並排,請使用者確認畫質;看得出差別就改用品質 95 再比一次。
- **Safari 不能存 WebP**:Safari 的 `toBlob('image/webp')` 會靜默變成 PNG。工具開啟時偵測(實際轉一張小圖看回傳的格式),
  不支援就在頁面上方顯示「請用 Chrome、Edge 或 Firefox 開這個工具」,「存進遊戲」按鈕停用。不選「Safari 存 PNG」:
  同一個資料夾混兩種格式,清單、快取、檢查都要多處理一種情況。

### 4.2 新的目標類型
| 類型 | 去背 | 成品 | 對齊 |
|---|---|---|---|
| 寵物、NPC(已有) | 要 | 256×256 | 腳底貼齊底邊正中央 |
| 主人 | 要 | 256×256 | 腳底貼齊底邊正中央 |
| 道具 | 要 | 64×64 | 置中,不用腳底對齊 |
| 樹與裝飾 | 要 | 256×256 | 腳底貼齊底邊正中央 |
| 地面材質 | 不要 | 256×256,可無縫拼接 | — |
| 登入主視覺 | 不要 | 1536×1024 | — |
| Logo | 要 | 保留原比例,長邊 1024 | 置中 |

- **地面材質的無縫化**:原圖(1024)先縮成 256,再把圖位移一半寬高,在接縫處用附近的像素融合,讓左右、上下接起來看不出縫。
  工具預覽畫面同時顯示 3×3 拼起來的樣子,讓使用者看得出重複感。
- **NPC 的招牌寵物**:寵物要跟 NPC 的身體連在一起。「清除雜點」只留跟最大一塊相連的部分,沒連在一起的寵物會被當成雜點清掉。
  繪圖 prompt 要寫明寵物貼在 NPC 身上(坐在頭頂、趴在背包上、抱在懷裡)。

### 4.3 批次模式
- 列出 `art-src/` 裡「還沒處理」的原圖:有原圖但沒有成品,或原圖的修改時間比成品新。
- 一次全部去背,排成縮圖;每張縮圖下面標代號和判斷出來的類型。
- 一個按鈕把全部存進遊戲;有問題的點縮圖進入單張模式修(調容許值、筆刷、翻轉)。
- 伺服器的 `art-src/` 清單要附上每個檔案的修改時間,才判斷得出「原圖比成品新」。
- 批次一律用預設的去背設定(容許值 40、柔邊 28、清掉小碎塊 2%、上方留白 4、不翻轉、不像素化)。要調的點縮圖進單張模式。
- 主圖先做。動作圖用同一批做出來的主圖對齊大小,同一批沒有就用遊戲裡的主圖。
- 下面這些情況那張標紅、寫原因,按「全部存進遊戲」時跳過,其他照存。標紅的點縮圖進單張模式,還是可以手動存。
  - 檔名對不上任何一張圖。
  - 兩張原圖對到同一張成品(例如 `噗噗.png` 和 `poring.png`):第二張標紅。
  - 灰白格子背景(假透明)。選標紅不存,不選「標警告照存」:照存的話格子會殘留在成品裡,要進遊戲才看得清楚(2026-10-14 與使用者確認)。
  - 動作圖在遊戲裡和同一批裡都沒有這隻的主圖。選標紅不存,不選「塞滿畫布照存」:照存的話攻擊、受傷、睡著會跟主圖忽大忽小,
    主圖做好後要重做(2026-10-14 與使用者確認)。照產圖順序(第 1 批主圖、第 3 批動作圖)幾乎不會發生。
  - 去背之後什麼都沒剩。
  - 存檔時伺服器拒絕:顯示伺服器回的訊息。
- 瀏覽器存不了 WebP 時(第 4.1 節),「全部存進遊戲」跟「存進遊戲」一樣停用。

### 4.4 Claude 先看原圖
使用者把一批原圖放進 `art-src/` 後告訴 Claude,Claude 逐張看過再進去背工具,檢查:
角色被裁到(尾巴、耳朵、翅膀出框)、身體朝左、灰白格子背景(假透明)、一張圖裡有多隻、有文字或浮水印。
有問題就列出檔名和原因,讓使用者重畫或在工具裡處理(朝左就勾水平翻轉)。

## 5. 美術進度表(`public/tools/art-status.html`)
- 一頁列出所有要畫的圖:寵物(主圖、3 種動作圖)、主人 10 張、NPC 6 張、道具 16 張、登入畫面、地面、樹與裝飾。
- 每一格三種狀態:**已進遊戲**(顯示成品縮圖)、**有原圖還沒處理**、**還缺**。
- 頁面上方顯示各類別的完成數,例如「寵物主圖 12 / 40」。必要的跟可有可無的分開算:
  寵物主圖 40、寵物動作圖 42(初階 13 種 + 炎龍)、主人 10、NPC 6、道具 16、登入畫面 2、地面材質 6(先試草地)、樹與裝飾 9;
  可有可無的中高階動作圖 78、主人施法 10 另外列。必要的加起來 131 張,跟第 1 節的驗算一致。
- 資料來自伺服器的圖片清單(`/assets.json`),不用另外維護一份清單。要畫哪些圖、每張接受哪些原圖檔名(第 3 節),
  由伺服器在清單裡一起列出;去背工具認原圖也用同一份,兩頁對同一個檔案的判斷才不會不一樣。
  不選「各頁自己寫一份對照表」:主人、道具等類型陸續加進去背工具時,兩份很容易改了一份忘了另一份。
  這份清單只在工具頁讀 `/assets.json?catalog=1` 時附上。遊戲登入時讀的 `/assets.json` 不帶:
  2026-10-14 實測,帶了會從 5.6KB 變成 43KB,而且遊戲每次登入都整份重新下載。
- 已進遊戲、但原圖比成品新的:顯示成品縮圖,加註「原圖比較新」(批次模式會重做這張)。
- `art-src/` 裡對不上任何一張圖的檔案,列在頁面最下面,方便抓檔名打錯的。
- 去背工具還沒支援的類型(例如主人在第 5 項之前):進度表照樣算「有原圖還沒處理」;
  批次模式那張標紅,寫「去背工具還沒支援這類圖」,不寫「檔名對不上」。

## 6. 伺服器:圖片清單、存檔、快取
現況(2026-10-13 已讀 `server.py`):
- `/assets.json` 只列 `pets/`、`npcs/` 底下的 `.png`;`/api/art` 只接受 PNG 檔頭、只接受 `pets/`、`npcs/` 兩個資料夾。
- `MIME` 沒有 `.webp`。
- 所有回應都是 `Cache-Control: no-cache`,而且沒有 `ETag` / `Last-Modified`,所以每次進遊戲每張圖都整張重新下載。

要改的:
- 清單列出 `pets/`、`owners/`、`npcs/`、`items/`、`ui/`、`ground/`、`deco/` 的 `.webp`,網址帶版本號(檔案修改時間,沿用 `v`)。
- `/api/art` 接受 WebP 檔頭(`RIFF....WEBP`),檔名依第 3 節的規則檢查;代號不在清單裡(例如不存在的種族、道具)就拒絕。
  仍然只接受本機連線(沿用 `is_local`)。
- `MIME` 加 `.webp: image/webp`。
- `/assets/` 底下的檔案,網址有帶 `v` 時回 `Cache-Control: public, max-age=31536000, immutable`;
  其他路徑(`index.html`、`*.js`、`/assets.json`)維持 `no-cache`。圖一換,修改時間變了,網址就變了,不會讀到舊圖。

## 失敗時的行為
| 狀況 | 行為 |
|---|---|
| 圖片讀不到、還沒讀到 | 那個角色用程式繪圖,不報錯、不擋登入(沿用現在 `loadArt` 的 `onerror`) |
| 主人只有男版圖、沒有女版 | 女角用程式繪圖,不拿男版代替 |
| 地面材質沒有 | 那種地形用程式繪圖 |
| Logo 沒有 | 顯示現在的網頁字 |
| 去背工具在 Safari 打開 | 頁面上方提示改用 Chrome / Edge / Firefox,「存進遊戲」按鈕停用 |
| 去背工具存檔被伺服器拒絕(檔名不符、不是 WebP、太大、不是本機) | 顯示伺服器回的訊息,不寫入任何檔案 |
| 批次模式裡有一張失敗(哪些算失敗見第 4.3 節) | 那張標紅色、寫原因,其他照存 |
| 登入訊息帶了不合法的性別 | 當作男,不回錯誤 |

## 驗收標準
- 無頭測試在 Mac 的 Python 3.8.20 全過:`python3.8 tests/test_phase1.py`、`test_phase2.py`、`test_phase3.py`,
  加上新的 `test_phase4.py`。merge 回 main 前在 Windows 的 3.8.5 再跑一次。
- `test_phase4.py` 至少涵蓋:新角色選女存檔後重新登入還是女;舊存檔沒有 `sex` 登入是男;不合法的性別當作男;
  存檔檢查接受 `pets/poring.webp`、`owners/knight-f.webp`、`items/red_potion.webp`,拒絕 `../`、不存在的代號、
  PNG 檔頭冒充 WebP;圖片清單列得出 `.webp`;有帶版本號的 `/assets/` 回應是長快取,`/assets.json` 是 `no-cache`。
- 第二次進遊戲時,瀏覽器開發者工具的 Network 分頁裡 `/assets/` 的圖片全部顯示從快取讀取(memory cache 或 disk cache)。
- `public/assets/` 裡沒有任何 `.png`(`find public/assets -name '*.png'` 沒有輸出)。
- 比例對照頁的戰鬥隊形模式,用最擠的組合(6 位主人 + 6 隻寵物 vs 6 隻皇家獅鷲)顯示「重疊 0 組」。
- 「美術」開關切到「程式」時,所有角色、地面、圖示都用程式繪圖,沒有空白或錯位;切回「圖片」也一樣。
- 去背工具在 Safari 打開時顯示提示,而且「存進遊戲」按鈕是停用的。
- 使用者在瀏覽器實際玩一輪(登入、走到野外、戰鬥、跟 NPC 對話、開背包和商店)並確認畫面,才 merge 回 main。
